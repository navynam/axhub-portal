# AX-HUB 개발가이드 (초급 개발자 온보딩)

> 대상: 오늘 처음 이 프로젝트를 여는 **초급 개발자**
> 목표: **하루 안에** 로컬 실행 → 폴더 지도 이해 → 새 화면 추가 → 새 API 연결까지 손으로 해본다.
> 이 문서는 실습형이다. 전체 구조는 [ARCHITECTURE.md](./ARCHITECTURE.md) 를 함께 참고한다.

## 0. 5분 만에 실행하기

```bash
# 1) 프론트 (Node 18+ 권장)
npm install
npm run dev            # → http://localhost:5173  로 접속

# 2) (선택) 백엔드 (JDK 17)
cd backend && ./gradlew bootRun    # → http://localhost:8080
```

- 프론트는 **백엔드 없이도 단독으로 동작한다**(목데이터). 처음엔 `npm run dev` 만으로 충분하다.
- 화면 우측 상단 **[사용자] / [관리자]** 토글로 역할을 바꿔볼 수 있다(관리자만 보이는 메뉴가 있다).
- **테마 체험**: 우측 상단 ⚙ → 5가지 테마 전환. 새로고침해도 유지된다(`localStorage`).
- **핵심 시나리오 한 번 돌려보기**:
  1. 사용자로 에이전트 카탈로그에서 도구 권한이 없는 에이전트의 **도구 권한 요청**
  2. 헤더에서 **관리자**로 전환 → 마이페이지 **승인함**에서 **승인**
  3. 다시 **사용자**로 → 해당 에이전트 **실행(대화)** 가능해짐

```bash
npm run build          # 프로덕션 번들 → dist/
npm run preview        # 빌드 결과 미리보기
```

## 1. 폴더 지도 — "여기엔 이런 걸 넣는다"

| 경로 | 여기엔 이런 걸 넣는다 | 안 넣는다 |
|------|----------------------|-----------|
| `src/pages/*.vue` | **화면 하나 = 파일 하나.** 레이아웃 + 화면 상태(ref/computed) + UI | `fetch` 직접 호출, 무거운 비즈니스 로직 |
| `src/components/*.vue` | 여러 화면에서 재사용하는 조각(모달·pill·아이콘·트리 등) | 특정 화면 전용의 큰 로직 |
| `src/store/state.js` | 앱 전체가 공유하는 **전역 상태 필드** | 표시용 임시 값(그건 화면 ref) |
| `src/store/modules/*.js` | 상태를 바꾸는 **액션 함수**(도메인별) | HTTP 통신(그건 service) |
| `src/features/*/services/*.js` | **백엔드 통신 + USE_API 분기.** mock↔실서버 경계 | 화면 상태 |
| `src/shared/api/` | `config.js`(USE_API/토큰), `http.js`(fetch 래퍼) | 도메인 로직 |
| `src/shared/constants/enums.js` | 상태/권한/역할 등 **상수**(매직 문자열 방지) | — |
| `src/shared/utils/format.js` | 날짜·숫자·문자 **포맷 함수** | — |
| `src/data.js` | 목데이터 seed(에이전트·지식·요청·보드·리소스·트리) | 실서버 붙으면 service 가 대체 |
| `src/styles.css` | 디자인 토큰(:root) + 4개 테마 오버라이드 | 컴포넌트별 산발적 색상 하드코딩 |
| `backend/.../com/axhub/<도메인>/` | Controller·Service·Repository·domain·dto | — |

> **황금 규칙**: 화면 → `store 액션`/`service` → `http.js` → 백엔드. 화면에서 한 단계를 건너뛰지 않는다.

## 2. 실습 A — 새 화면(기능) 추가하기

예제로 **"공지사항"** 화면(page 키 `notices`)을 추가한다. 실제 파일에서 고칠 곳은 **딱 3곳**이다.

### 단계 1 — 화면 파일 만들기 `src/pages/Notices.vue`

기존 화면(`Community.vue`)과 같은 패턴을 그대로 따른다.

```vue
<script setup>
/**
 * 공지사항 — 사내 공지 목록 (실습 예제)
 */
import { computed } from 'vue'
import { store } from '../store.js'
import Icon from '../components/Icon.vue'

// 지금은 화면 안 샘플. 실제로는 store/service 로 대체한다(아래 단계 4).
const notices = computed(() => store.notices || [])
</script>

<template>
  <div>
    <div class="page-head">
      <div class="eyebrow">알림</div>
      <div class="page-title">공지사항</div>
    </div>
    <ul class="agent-list">
      <li v-for="n in notices" :key="n.id" class="acc-card">
        <Icon name="bell" :size="16" /> <b>{{ n.title }}</b> <small>{{ n.date }}</small>
      </li>
    </ul>
  </div>
</template>
```

### 단계 2 — 라우팅 등록 `src/App.vue` (세 곳을 함께)

```js
// (a) import 추가
import Notices from './pages/Notices.vue'

// (b) pages 매핑에 키 추가  ← 이 키가 store.page 값이 된다
const pages = { home: Home, agents: Agents, /* ... */, notices: Notices }

// (c) 헤더 타이틀 추가
const titleMap = { home: 'AX HUB', /* ... */, notices: '공지사항' }
```

### 단계 3 — LNB 메뉴에 노출 `src/App.vue`의 `nav`(computed)

```js
// 최상위 메뉴로 추가할 때 (ico 는 components/Icon.vue 의 path 딕셔너리 키 중 하나: home/bot/book/chat/bell ...)
{ key: 'notices', label: '공지사항', ico: 'bell' },
```

- 하위 메뉴로 넣으려면 부모의 `children` 배열에 `{ key, label, page: 'notices' }` 를 추가한다.
- **관리자 전용**으로 만들려면 `if (store.role === 'admin')` 블록 안에 넣는다(기존 `시스템 관리` 참고).
- 메뉴 클릭 → `openNav`/`openChild` → `go('notices')` → `store.page='notices'` → `pages['notices']` 렌더. **끝.**

> 화면 이동은 어디서든 `import { go } from '../store.js'` 후 `go('notices')` 로 한다. `store.page` 를 직접 수정하지 말 것(액션을 쓴다).

### 단계 4 — 데이터 연결 (목 → 서비스)

**(4-1) 목데이터**: 빠르게 확인하려면 `src/store/state.js` 에 필드를 추가하고 `src/data.js` 에 seed 를 만든다.

```js
// src/data.js
export const seedNotices = [
  { id: 'nt-1', title: '7월 정기점검 안내', date: '2026-07-20' },
]
// src/store/state.js  (reactive store 객체 안)
import { /* ... */ seedNotices } from '../data.js'
export const store = reactive({ /* ... */, notices: seedNotices })
```

**(4-2) 서비스(권장 최종형)**: `features/` 에 service 를 만들어 통신 경계를 둔다(아래 실습 B 참고).

## 3. 실습 B — 새 API 붙이기 (mock ↔ 실서버)

핵심은 **"화면은 그대로 두고, service 안에서 `USE_API` 로 분기"** 한다는 것. 정답지는 `agentService.js` 다.

### 프론트 — service 작성 `src/features/notice/services/noticeService.js`

```js
import { http } from '../../../shared/api/http'
import { USE_API } from '../../../shared/api/config'
import { store } from '../../../store'

/** GET /notices — 공지 목록 */
export async function fetchNotices() {
  if (USE_API) return http.get('/notices')   // 실서버
  return store.notices                        // mock
}
```

- `http.get/post/put/patch/del` 만 있으면 된다. **JWT 헤더 첨부·에러 정규화·`{success,data,message}` 언랩**은 `http.js` 가 자동 처리한다.
- 화면에서는 `const list = await fetchNotices()` 처럼 **service 만 호출**한다. `fetch` 를 화면에 쓰지 않는다.

### 실서버 켜기 — 프로젝트 루트 `.env`

```
VITE_USE_API=true
VITE_API_BASE=http://localhost:8080/api/v1
```

> `.env` 가 없으면 `USE_API=false`(mock)로 동작한다. 값 변경 후에는 `npm run dev` 를 **재시작**해야 반영된다.

### 백엔드 — 대응 Controller (agent 도메인 패턴 그대로)

`agent` 패키지를 복사하듯 5개 파일을 만든다: `NoticeController → NoticeService → NoticeRepository → domain/Notice → dto/NoticeResponse`.

```java
@RestController
@RequestMapping("/api/v1/notices")   // 프론트 http.get('/notices') 와 매핑 (API_BASE=/api/v1)
@RequiredArgsConstructor
public class NoticeController {
    private final NoticeService service;

    @GetMapping
    public ApiResponse<List<NoticeResponse>> list() {
        return ApiResponse.ok(service.getNotices());   // 항상 ApiResponse 로 감싼다
    }
}
```

- 응답은 **반드시 `ApiResponse.ok(...)`**. 그래야 프론트 `http.js` 가 `data` 만 깔끔히 꺼낸다.
- 오류는 `throw BusinessException.notFound("...")` 처럼 던진다 → `GlobalExceptionHandler` 가 `{success:false, message}` 로 변환.
- 엔티티를 그대로 반환하지 말고 **`record` DTO(`NoticeResponse.from(entity)`)** 로 변환한다.

## 4. 자주 하는 실수 / 주의 (이 소스에서 실제로 지키는 규칙)

1. **화면에서 `fetch` 직접 호출 금지.** 통신은 `features/*/services` 안에서만(`USE_API` 분기). 화면은 store/service 만 부른다.
2. **`store.page` 직접 대입 대신 `go(page)`** 를 쓴다. page 키는 `App.vue` 의 `pages` 매핑에 반드시 등록돼 있어야 화면이 뜬다(오타 주의).
3. **SVG 차트의 `stroke`/`fill`/`stop-color` 에는 CSS 변수(`var(--x)`)가 안 먹힌다.** presentation 속성에는 CI 팔레트 **hex 를 직접** 쓴다(예: `SysMonitor.vue`/`ItOps.vue` 의 `#0046FF`·`#0E8A66`·`#D2403A`). 일반 요소 스타일은 반대로 **토큰 변수만** 쓴다.
4. **매직 문자열 금지.** 권한/상태/역할 값은 `shared/constants/enums.js`(`Perm.GRANTED` 등)를, 날짜/숫자 표시는 `shared/utils/format.js`(`today()`/`comma()`)를 쓴다.
5. **공통 영역(`shared/*`, `store/state·index·ui·session·meta`, 공통 컴포넌트, `styles.css`) 수정은 개발자 E 리뷰 필수.** 여러 화면이 함께 깨질 수 있다.
6. **새 아이콘**은 `components/Icon.vue` 의 `paths` 딕셔너리에 SVG path 를 추가한 뒤 `<Icon name="..." />` 로 쓴다(임의 이미지 삽입 금지).
7. **에이전트 실행이 막힐 때**는 버그가 아니라 규칙이다: `agentReady(agent)` — 사용 도구를 하나라도 미보유(`none`/`denied`)하면 실행 불가. 도구 권한을 요청·승인 받아야 열린다.
8. **`.env` 변경/설치 후에는 dev 서버 재시작.** Vite 는 `import.meta.env` 를 시작 시점에 주입한다.
9. **모달은 상태 플래그로 연다.** 권한요청=`store.modal`, 반려=`store.denyModal`, 설정=App.vue 지역 `showSettings`. 새 전역 모달을 만들면 App.vue 에서 렌더 조건을 걸어준다.

## 5. 디버깅 · 빌드 확인 체크리스트

**화면이 안 뜰 때**
- [ ] `App.vue` 의 `pages` 매핑에 그 page 키가 있는가? (없으면 `Home` 으로 폴백)
- [ ] `go('키')` 의 키와 `pages`/`titleMap`/`nav` 의 키가 **철자까지** 일치하는가?
- [ ] 관리자 전용 화면이면 헤더에서 **[관리자]** 로 전환했는가?

**데이터가 안 보일 때**
- [ ] `USE_API` 가 의도한 값인가? (mock 인데 실서버 기대 X) → 브라우저 콘솔에서 네트워크 탭 확인
- [ ] 실서버 모드면 백엔드가 `:8080` 에 떠 있고 CORS(`application.yml` allowed-origins=5173)가 맞는가?
- [ ] 응답이 `{success,data,message}` 형태인가? (아니면 `http.js` 가 언랩하지 않고 원문 반환)

**권한/승인 흐름이 이상할 때**
- [ ] 도구 권한 상태(`store.resources[name].perm`)가 `granted` 인가? (`agentReady` 판정 기준)
- [ ] 승인은 **관리자 역할 + 승인함(view=approve)** 에서만 가능하다.

**빌드 확인**
- [ ] `npm run build` 성공(에러 0) → `dist/` 생성
- [ ] `npm run preview` 로 프로덕션 번들이 정상 동작
- [ ] 콘솔 경고(정의 안 된 컴포넌트/누락 prop) 없는지 확인
